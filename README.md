### 2026-09-05（六）

#### 🐛 跨店支援：支援日在班表上一律顯示成「休」

同仁回報「支援都會變休」。實例：潘奕廷 9/11（週五）聯鑫記錄是 `排休`、美德那格是 `23-07 supportEmp=聯鑫-潘 approved`，首頁卻顯示「休 🆘美德」。

**原因**：PULL 認領制下，被派出去支援的人**在本店那格本來就是排休**（人不在本店），真正的班記在**接收門市**的 `🆘待補X` 格（靠 `supportEmp='{本店}-{短名}'`＋`approved` 認人）。但顯示端寫成「本店排休 → 直接判休」，讓一筆等於「今天不在這裡上班」的記錄贏過「今天實際去哪上班」的記錄。

有意思的是**產圖（列印班表）一直是對的**——`drawSchedule` 的註解明寫「新模型下支援者本店多為休假，故不要求本店有班也要顯示」，只有螢幕端漏掉，所以列印出來的紙本跟手機上看到的不一樣。這次全部對齊產圖那條規則：

| 位置 | 修正前 | 修正後 |
|---|---|---|
| schedule-V2 班表格 | 排休格直接略過支援班 → 顯示「排休」 | 整格顯示 `23-07`＋`支援美德` |
| 首頁本週班表 | 「休」＋🆘美德 | 綠底 `23-07`＋🆘美德 |
| 首頁個人月曆 | 「美德／排休」 | 「美德／23-07」 |
| 首頁今日班別徽章 | 「今日休假」 | `⏰ 23-07　🆘 美德` |
| 首頁打卡卡片 | 「今日無排班」，在美德打完卡還一直催打卡 | 抓得到支援班與**該店的**打卡紀錄 |

規則統一為：本店空白或排休/指休 → 顯示支援班；本店有實班（同日兩頭跑）→ 維持本店班＋🆘 標記，不讓支援班蓋掉主班。

- ⚠️ **資料完全沒動**：班表格整格顯示支援班只是即時衍生（`loc=支援X`），`syncUIToMemory` 本來就會跳過這種格子不落地（避免又生出雙軌 set#1），本店那筆排休記錄原樣保留。薪資／成本仍只認接收門市那套（`supportEmp`＋`approved`），`isEmpRecord` 早就是「當天有支援就排除本人記錄」，這次只是把畫面對齊既有的計算口徑。
- ⚠️ **打卡卡片只有「本店今天查無班」才多讀他店**（3 次讀取），正常上班日零額外成本。原本它只查本店 `weeks` 與本店 `attendance`，但支援日的班與打卡都在對方店裡，所以支援日既看不到班、也看不到自己已經打過的卡。

#### 🐛 經營績效→統計分析：切換門市後看不到最新月份（8 月不見）

**原因**：期間選單的 `anaFrom/anaTo` 是全域變數，**換門市時不重設**。加盟主/admin 進頁面預設是 `stores[0]`＝美德（損益最新只到 7 月）→ `anaTo` 被設成 `2026-07`；再切到已輸入 8 月的聯鑫時，`2026-07` 在聯鑫也存在、通過了「該月份是否有效」的檢查 → 範圍沒被拉開，**8 月被自己的期間篩選濾掉**。重整頁面後直接選聯鑫就正常，所以很難重現。

#### ⚙️ 跨店支援：發給「被支援店」的通知全部取消（2026-09-03 追加）

「被支援店」＝外店員工來本店的那一方（`requestingStore`，同 `被支援費用` 的口徑）。`approved`／`filled`／`cancelled` 三種都是**自己發出的請求得到回應**——人是自己要的、缺口是自己開的，結果在班表上看得到，屬於「知悉」不是「行動」。

保留的兩條都是「對方不知道、不做會出事」：`request` → 被請求店（不審核人就不會出現）、`cancelled` → 只發被請求店（本來要借出的人被取消，那邊班表要收回來）。

⚠️ 這樣被支援店會對「支援被取消／缺口沒人認領」完全無感，所以**摘要新增「🆘 待補缺口 N 格（本週＋下週）」區塊**補回來——那則本來就會發，不多花額度，而且比逐事件通知更接近店長真正要看的東西：「我現在還缺幾個人」，而不是「剛剛發生了什麼」。上線當下實測抓到美德下週一 23-07 一格無人認領。

⚠️ **這份預算是照「18 人綁定 LINE」算的**。在職 34 人，**綁定人數一過 25 人就會再爆一次**——屆時員工端只能留「薪資發布」與「缺卡提醒」兩條，其餘得靠 App，或改推門市群組（群組算一個收件人）／查詢類改走 reply（免費）／升級方案。

#### 🐛 `arrayUnion` 靜默丟棄重複紀錄：撤回後再發放，帳本完全沒變

- **症狀**：「發放應休未休 → 撤回 → 再發放」，第二次發放跑完顯示「✅ 已發放」，但 `comp/2026` 仍是 `earned:0`、`leaveLog` 也沒有新紀錄。
- **根因**：Firestore 的 `arrayUnion` **不會加入已存在的相同元素**。重新發放產生的 `comp_earn` 每個欄位都與第一次那筆一模一樣（`date`/`type`/`source`/`days`/`note`/`savedBy`），被判定為重複而**靜默丟棄**。整條路徑「成功」卻什麼都沒發生。
- 同樣的坑也在「發放→撤回→再撤回」（`comp_cancel` 也沒有唯一欄位）。
- **修正**：所有 `leaveLog` 的 `arrayUnion` 紀錄一律帶 `ts: Date.now()`（`salary-page.js` 6 處、`leave-page.js` 2 處）。
- ⚠️ **診斷過程本身也踩到快取**：第一次驗證仍失敗，是因為頁面跑的是 SW 快取裡的舊 JS。用 `fn.toString()` 比對才確認。**改完務必確認執行中的版本，不要只看伺服器上的檔案。**

#### 🐛 首頁打卡卡在**週日**抓錯班別（每個週日都讀成週一的班）

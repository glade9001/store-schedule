# 劃休功能優化 — 細部規格（配額 + 優先序 + 首頁提醒）

> 狀態：規格草案（尚未實作）

| 項 | 定案 |

## 1. Settings（`settings.html`）— 修正＋新增

現況：已有「每週劃休上限」欄（`quotaFullTime`/`quotaPartTime` → `config/shifts.leaveQuota`），但 leave-request 實際當「**每日**」用 → **標籤誤導**。

改為：
```
每日劃休上限
  正職：[ 2 ] 人/天
  工讀：☑ 不受每日上限   （勾選＝不限；取消勾選才顯示數字欄）
每週劃休上限
  正職：[ 2 ] 天/週
```
- 資料：`config/shifts.leaveQuota = { fullTime: 2, partTimeUnlimited: true, partTime: null, weeklyFull: 2 }`
- 相容舊值：無 `partTimeUnlimited` 時沿用舊 `partTime` 數字。

## 2. 劃休配額判定（`leave-request.html`）

### 2.1 名額計算（某日 D）
- **當天在休人數（顯示用）** = 該日所有 `leaveRequests`（off/annual/comp，status 非 cancelled/unfulfilled）人數。
- **排休名額判定（擋用）**：只數 `type==='off'` 的正職人數 vs `dailyLimits.fullTime`。
- **工讀**：`partTimeUnlimited` 時完全不判配額（只顯示）。

### 2.2 送出時的提示（軟擋）
- 正職排休、且該日正職排休數 ≥ 上限 → 「⚠️ 此日正職名額已滿（上限 N），你是候補第 M 位，仍可送出，請與店長協調」→ **仍允許送出**。
- 未滿 → 「此日正職排休 K/N」。
- 工讀（不限）→ 不跳配額警告，只顯示「當天已有 X 人在休」提醒人力。

### 2.3 每週上限（正職，硬擋，沿用）
- 正職該週排休已達 `weeklyFull`（預設 2）→ 硬擋不可送（現行行為，改讀設定值）。

## 3. 優先序（`createdAt` 先送先贏）

### 3.1 排序
同一天的 leaveRequests 依 `createdAt` 升冪 = 順位（第 1 位最優先）。

### 3.2 顯示三處
1. **申請當下**（送出前預覽 + 送出後）：「你是這天第 **M** 位劃休（上限 N）」；M > N 時標「候補」。
2. **同日劃休者清單**（現有 `othersBox` 延伸）：依 createdAt 排序、標順位與時間
   `① 農芯 7/26 09:12`／`② 亦婷 7/25`／`③ 你（候補）`。
3. **店長端**（`schedule-V2.html` 劃休標籤 / `leave.html`）：某日超額時依順位呈現，供「先到先准」裁決。

> 意義：軟配額＋順位＝排隊模式，超額不擋死、但公平（誰先送誰優先）。

## 4. 首頁劃休提醒（`home.html`）— 鼓勵、可關

### 4.1 顯示條件（全部成立才顯示）
1. 目標週（下週）劃休**已開放**（在截止日前；沿用 `getDeadlineForWeek`／下週劃休開放狀態）。
2. 本人該週**尚無** leaveRequest（off/annual/comp，非 cancelled）。
3. 本人**未按關閉**該週提醒（`localStorage: leaveHintDismissed_{週}`）。

### 4.2 樣式（友善、非紅色警告）
`📅 下週劃休已開放，需要休假記得去劃休～` ＋ `[去劃休]`(→leave-request.html) ＋ `[✕ 知道了]`

### 4.3 行為
- **有劃休** → 條件2不成立 → 自動消失。
- **按 ✕** → 寫 `localStorage` → 該週不再提醒（鼓勵不嘮叨）。
- 換週（新的一週開放）→ 新的 key → 再提醒一次。

> 與薪資簽收提醒的差異：簽收**必做**（未簽一直提醒、不可關）；劃休**選做**（可關、關了不吵）。

## 5. 候補自動遞補（B）

**核心：順位與「是否在名額內」一律 live 由 `createdAt` 排序即時推導，不存固定狀態** → 有人取消，後面自動往前遞補，無需手動重排。

- **推導**：某日某角色的劃休依 `createdAt` 升冪排序，第 1..N 位 = 在名額內、第 N+1 位起 = 候補。任何人取消（status→cancelled）即從序列移除 → 後面每人位置自動 −1 → 候補自動遞補進名額。
- **狀態顯示**：員工在 `leave-request.html`／`home.html` 看到自己該日的**即時狀態**：`✅ 已在名額內`／`候補中（第 M 位，上限 N）`。取消後再看即已更新。
- **遞補提示**：偵測「上次為候補、這次已進名額」→ 在 `leave-request`／`home` 顯示一次友善提示「你 X/X 的劃休已遞補進名額 🎉」。
  - 實作：以 `localStorage` 記本人各日「上次看到的狀態」，載入時比對；由候補→在額內即跳提示。（**非即時推播**——在下次開頁時反映；本站無推播基礎設施。）
- 工讀（不受限）永遠視為「在名額內」，不參與候補。

## 6. 員工挑日更聰明（C）

### 6.1 劃休月曆每日熱度
`leave-request.html` 月曆每格顯示當日在休概況，顏色分級引導避開額滿日：
- 顯示：`休 2`（含 off/annual/comp 的當天在休人數）；正職排休接近/達上限時標記。
- 色階（以正職排休名額為準）：**綠=有空** / **黃=快滿（剩 1）** / **紅=已滿**。
- 工讀不限：不以工讀染色，僅併入「在休人數」數字。

### 6.2 申請 Modal 即時剩餘名額
開啟某日申請時顯示：`這天正職排休名額 1/2，還剩 1`（工讀不限則顯示「工讀不受上限」＋當天在休人數）。送出後即時更新。

> B、C 都是「讀 leaveRequests + 配額即時推導」，無新資料欄位（`createdAt` 已有）。

## 1. 兩層架構

```
指標層（事實）  ──►  決策層（行動）
每工時成本/加班佔比/    目標門檻+合理範圍帶 → 紅黃綠
總成本(含公司負擔)/     加班可省估算($)
結構(正職vs工讀/組成)/  人力配置建議(規則)
趨勢(MoM/YoY/滾動)      成本預測(下月/年度)
```
決策層必須站在可信指標之上，故資料一律源自指標層（同一份計算）。

---

## 2. 指標層（efficiency metrics）

**成本定義（重要）：總人事成本 = 實發薪資(gross) + 公司負擔(勞保雇主+健保雇主+勞退6%)。** 只看實發會低估 2–3 成。

| 指標 | 公式 | 資料來源 |
|---|---|---|
| 每工時人事成本 | (Σ gross + Σ 公司負擔) ÷ Σ 總排班工時 | gross/er 讀**快照**；工時取 `weeks` 排班 `actualHours`，依班次日期歸月（沿用 analytics 現有 supportMap 的歸月邏輯，擴及全體） |
| 加班費佔比 | Σ 加班費 ÷ Σ 總薪資 | 皆現有 |
| 加班時數佔比 | Σ 加班工時 ÷ Σ 總工時 | otHours / actualHours(isOT) |
| 每人月均成本 | Σ 總成本 ÷ 在職人數 | 現有 |
| 結構：正職 vs 工讀 | 各自成本與人數佔比 | 用 `rec.role/rec.payAsPartTime`（快照）非現在主檔 |
| 成本組成 | 底薪/加給獎金/加班/國假/公司負擔 各佔比 | 快照欄位 |

- 呈現以**全公司合計**為頭條（避免跨店支援「發薪歸本店、工時在支援店」的歸屬混淆）；各店維持成本趨勢分列，per-store 每工時成本標註「支援時數歸屬」註記。

## 3. 決策層（decision aids）

### 3.1 目標門檻與合理範圍（Targets & range）
- 加盟主/admin 在設定頁設**目標門檻**，存 `settings/globalConfig.hrTargets`：
  - `costPerHourMax`（每工時成本上限）
  - `otRatioMax`（加班佔比上限，例 8%）
  - `laborCostRatioTarget`（人事費率目標%，需營收才生效）
- **合理範圍帶（自動）**：近 3–6 個月**滾動平均 ± 區間**（預設 ±1 標準差或 ±10%），畫在趨勢圖上。
- **狀態燈**：每指標每月對照門檻/範圍帶 → 綠(合理)/黃(接近)/紅(超標)。

### 3.2 加班可省估算
- 若加班佔比 > `otRatioMax`：估「若降到門檻可省 $ = 超出部分對應的加班費」，給具體金額 → 指向排班改善。

### 3.3 人力配置建議（規則式，非黑箱）
- 加班佔比連續 ≥ N 月超標 → 「建議增補人力／檢視排班密度」
- 某店每工時成本顯著高於其他店（> 平均 ×1.X）→ 「檢視該店薪資結構/人力配置」
- 跨店支援時數高且常態 → 「考慮常態化編制，減少調度成本」
- 工讀佔比 vs 正職 → 彈性/成本權衡提示（僅資訊，不強制）
- 每條建議標明「依據哪個指標、哪幾個月」，可稽核。

### 3.4 成本預測（基礎）
- **下月預估** = max(近 3 月滾動平均, 依已排班工時 × 近期平均每工時成本)。已排的下週/下月班表 × 平均時薪成本可提高準度。
- **年度累計(YTD) + 全年預估**（YTD + 剩餘月份預估）。
- 全部**明確標示「預測/估計」**，與實績視覺區隔。

### 3.5（選配）營收解鎖
- 若加盟主願每月手動輸入各店營收（存 `settings/globalConfig.revenue[ym][store]` 或 `stores/{store}/revenue/{ym}`）：
  - 解鎖 **人事費率 = 人事成本 ÷ 營收**、**人效 = 營收 ÷ 工時 / 營收 ÷ 人**。
  - 這是判斷「合理範圍」的黃金指標，優先於範圍帶。

## 5. 歷史不可變鐵則（務必遵守，見記憶 feedback-historical-immutability）

- **歷史月份一律讀存檔快照**（`grossAmt/deductAmt/netAmt`、`laborEr/healthEr/pensionEr`、`rec.role/rec.payAsPartTime`），**不得用現在主檔重算過去**。
- **已發布月份維持唯讀**，不放寬。
- **缺薪資記錄的估算、以及所有預測**，一律標示為「估計/預測」，**不混入實績**（收斂現存缺口）。
- 角色相關分項（正職/工讀結構等）改讀 `rec.role/rec.payAsPartTime`，非現在主檔。
- 調職/離職：以記錄所屬 store 與 departDate 判定歸屬與是否計入，不因現況回改過去。

## 7. 模組 E-1：勞基法合規稽核表（優先 1）

> 只讀現有排班/薪資資料，**零寫入、零風險**；加盟主最想要（合規＝法律風險）。沿用 Phase 1 的偵測邏輯（見 [[project-labor-compliance]]）。

- **範圍**：可選期間（預設當月）× 門市 × 員工。
- **每人每月列出**：
  - 跨日間隔 < 11h 的次數（Phase 1 `shiftIntervalsWD`）
  - 連續工作 > 12h（中間無休息）次數
  - 當月加班時數累計、單日工時超時
  - 例假/休息日、國定假日出勤
  - **知情放行 `lawOverrides`** 清單：哪些違規被放行、誰、何時、理由
- **狀態燈**：綠(合規)/黃(已放行)/紅(未處理違規)。
- **匯出**（勞檢/存查用，CSV/表格）。
- **守鐵則**：歷史月份讀當時排班快照（weeks records），不因現況重算。

## 8. 模組 D：月加班 46h 預警（優先 2）

> 勞基法 §32：延長工時每月上限 **46h**（經工會/勞資會議同意可到 54h，每 3 個月不超 138h）。Phase 1 已有**單週**偵測，本模組補**月累計**維度，事前控成本＋合規。

- **即時累計**：排班/存檔時，計算每人**當月**加班時數累計。
- **分級預警**：接近（如 ≥ 40h 黃）/ 超過 46h（紅）/ 超過 54h（嚴重）。每 3 月 138h 亦追蹤。
- **呈現**：排班頁該員標記＋加盟主儀表板清單；可選 LINE 通知店長（沿用通知系統）。
- **資料**：schedule `isOT` 工時 + salary `otHours`；以班次日期歸月。
- **守鐵則**：預警是「當下營運控管」，用現行排班即時算；不回改歷史。

## 9. 模組 F：月度聚合 doc（優先 3）

> 讓儀表板不必每次掃全部 weeks+salary，解 analytics 效能。

- **資料**：`stores/{store}/monthly/{ym}`（或 `analytics/{store}_{ym}`）= 快照聚合：
  `{ totalGross, totalEr, totalHours, otHours, otPay, holidayPay, headByRole:{full,part,manager}, costByRole, updatedAt, source:'published'|'draft' }`
- **產生時機**：薪資**發布**時寫入（定版快照）；亦可提供「重算聚合」按鈕（僅未發布月）。
- **守鐵則**：聚合以**已發布月份的快照**為準；標示 draft/published 來源。歷史聚合一旦發布不再變動。
- 儀表板(E-rest)與預警趨勢優先讀此聚合，缺聚合才 fallback 即時算。
